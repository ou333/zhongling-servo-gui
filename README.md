# ZEKEEP指擎串口舵机标定工具

给串口舵机做 ID 标定、读数核对、机械零位标定和开机释力设置的本地工具。
HTTP 服务只用 Python 标准库，串口通信使用 pyserial；界面是单个内嵌
CSS/JS 的 HTML，不依赖任何 CDN。模块导入和服务启动都不会自动打开串口。

## 安装与启动

仓库：[ou333/zhongling-servo-gui](https://github.com/ou333/zhongling-servo-gui)。

环境要求：Python 3.10 或更高版本。以下命令适用于 Linux，串口枚举按
`/dev/ttyUSB*` 设计；无需安装 LeRobot 或配置 Conda 环境。

首次下载和安装：

```bash
git clone https://github.com/ou333/zhongling-servo-gui.git
cd zhongling-servo-gui
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

所有启动命令均在仓库根目录执行。已有本地副本时，进入该目录并激活 `.venv` 即可，
无需重复克隆。

先进行无硬件演练：

```bash
python -m servo_gui.server --simulate --simulate-profile assembled --port 8770
```

按 `Ctrl+C` 停止服务。连接真实设备时启动：

```bash
python -m servo_gui.server --port 8770
```

浏览器打开 <http://127.0.0.1:8770/>。服务只监听回环地址。
真机通信需要当前用户具有目标串口的读写权限。

## 连接与串口

串口下拉框**只列 `/dev/ttyUSB*`**（模拟模式额外多一个「模拟串口」）。
主臂走 USB 转串口适配器，正是这一类；过滤掉 `/dev/ttyACM*` 还能避免把从臂的
CAN 适配器误选成主臂。要放开这个过滤，改 `servo_gui/server.py` 里的 `PORT_PREFIX` 常量。
不带 `--simulate` 时也不会自动连接设备——只有调用 `/api/connect`，后台总线线程才会
创建串口句柄。所有串口访问都由该线程通过队列串行执行，HTTP 请求线程不直接碰串口对象。

## 三个标签页

**ID 标定** —— 改号时总线上只能连一个舵机。两个入口：

- **七个大按钮**：把总线上唯一在线的那个舵机改成对应编号。新舵机出厂都是 `000`，
  这条路径不需要你指定源 ID。
- **手动指定源 ID / 目标 ID**：填「当前 ID」和「目标 ID」再点「改号」，
  用于给已经有编号的舵机改号，例如 `002 → 003`。输入接受 `2` 或 `002`，回车等于点按钮。

两个入口走同一套后端校验：写入前强制扫描 0–10，要求**恰好只有一个 ID 响应且等于源 ID**，
否则拒绝，没有绕过入口。确认框需手输 `SET ID 00X`。
改号成功后**必定**追加一条 `#00XPCSM!`（开机释力），无开关；确认框里会列出这两条报文。

**舵机读数** —— 七路独立开关，开启后持续读取直到手动停止。
开启时默认先发一次 `PULK` 释力（否则舵盘拧不动），可用「保持力矩」关掉；
停止时**不发** `PULR`，关节保持可手动旋转。目标 PWM 由后端固定表提供，界面不可改。

**零位标定** —— 机械零位标定（`PSCK`）。

## 零位标定：五轴用 `PSCK`，002/003 只能手动

| ID | 零位目标 | 怎么标 |
|---|---|---|
| 001、004–007 | 1500 | 扶到机械零位 → 点「标定零位」发 `PSCK` |
| 002、003 | **2400** | **没有命令可用**，开读数后手动旋转舵盘对到 2400 |

**能把当前位置重映射成指定读数的命令只有 `PSCK`，而且只能映射成 1500。**
002/003 的零位取 2400，不是 1500，所以它们没有任何命令可用——
后端对这两个轴的 `/api/calibrate_zero` 直接返回 `manual_only` 并说明原因，
界面上也不显示「标定零位」按钮。

手册措辞的差别是关键：§14 `PSCK`「用于纠正偏差，**将当前位置设置为 1500 中间值**」是重映射；
§19 `PSMX`「**设置舵机最大值**……将舵机调节到合适位置后，发送此命令设置」写的是**行程上限**
这个独立参数（§20 `PCLEO` 把「矫正值 1500」和「最大值 2500」并列，二者不是一回事），
**不改变当前读数**。实测佐证：对 002 发 `#002PSMX!` 之后回读仍是 2403。

对 001 和 004–007，操作方式是**把关节扶到正确机械零位并扶稳**，然后执行标定——
命令会把当前物理位置直接定义为 1500，不需要先把舵盘拧到某个读数。
对 002 和 003，操作方式相反：开读数、手动旋转舵盘，把读数对到 2400，不发任何命令。

写入前连续采样三次，跨度超过 5 拒绝写入；写入后以 `PRAD` 回读为准，`#OK!` 不作为验证。

### 与外部遥操作系统配合

本仓库仅提供串口舵机标定工具，不包含 LeRobot 遥操作代码或其配置文件。
接入其他控制系统时，需让该系统中的零位读数与本工具的目标 PWM 表保持一致。

原 ZK-XM115 遥操作系统采用以下配置值（数组下标从 0 开始）：

| 字段 | 配置值 | 说明 |
|---|---|---|
| `pwm_ranges[1]`、`[2]` | `[500, 2400, 2500]` | 中间值为 002、003 的零位读数 |
| `joint_ranges_deg[1]` | `-229.86486486486487` | ID 002 的比例映射满程角度 |
| `joint_degrees_per_pwm[2]` | `0.12162162162162163` | ID 003 的传动比，等于 `90/740` |

ID 002 的满程角度按 `90 / (740 / (零位 - 500 - 死区))` 计算，死区为 10。
零位为 2400 时，零位以下可用行程为 1890 个计数；修改零位时必须同步重算满程角度，
否则会改变控制增益。原系统验证中，PWM 1650 在两个轴上均映射为 −90°。
这些数值针对原机械结构，接入其他机械臂时应按实际传动关系核对。

### 标定瞬间会动，必须扶住

`PSCK` 改的是矫正值，也就是坐标原点。原点一移，舵机内部那个目标位置寄存器对应的
物理位置就跟着偏；只要力矩是通的，它会立刻朝新坐标下的旧目标冲过去——机械零位离原
1500 越远，动作越猛。本工具在写入后通过 `finally` 补发一次 `PULK`，
并把补发排在回读**之前**，把力矩接通的窗口压到最小。
即便如此，写入到补发之间的一瞬间挡不住，**执行时必须用手扶住关节**。

## 开机释力（`PCSM`）

界面上**没有**独立的开机释力卡片，也没有开关。`PCSM` 只有一个入口：ID 标定页改号
成功后自动追发，确认框里会把这两条报文都列出来。`/api/startup_torque` 接口仍然保留，
需要补发或用 `PCSR` 回退时用命令行调：

```bash
curl -s -X POST -H 'Content-Type: application/json' \
  -d '{"id":1,"mode":"restore","confirm_text":"PCSR 001"}' \
  http://127.0.0.1:8770/api/startup_torque
```

`mode` 取 `release`（`PCSM`）或 `restore`（`PCSR`），`confirm_text` 必须是 `PCSM 00X` / `PCSR 00X`。

### 两个约束

依据：众灵舵机使用手册（250508 版）第五章第 16、17 条。手册未随本仓库分发，
使用其他型号或固件时请向厂商核对对应版本。

1. **`PCSM` 与 `PCSD` 互斥。** 发过 `PCSM` 之后「设置上电启动位置」永久失效，
   本工具因此不提供 `PCSD`——`/api/startup_position` 固定返回 501 并说明原因。
2. **写完无法用软件确认。** 手册里没有任何命令能读回「开机释力 / 开机恢复扭力」
   当前状态；`#OK!` 只代表命令被接受。唯一验证方式是断电 → 重新上电 → 用手拧舵盘。
   界面和日志里不会出现「已验证生效」这类措辞。

## 实测硬件行为（固件 `ZL-ZServo_AD_CBM V2.1.16STG`，2026-09-11）

原项目通过诊断脚本在真机上记录了以下两条行为，本工具已据此处理。
诊断脚本未随本仓库分发；以下记录针对上述固件版本：

**1. 持久写的回包比读命令慢一个量级。** 同一台舵机上 `PVER` / `PRAD` / `PMOD`
均 ≤20 ms 回包，而 `PCSM` 用了 **60 ms**。`bus.py` 的 `command()` 固定 sleep 30 ms
后 `read_all()`，正好错过，会把成功的写误判成「无回包」。
因此所有持久写（`PID`/`PSCK`/`PSMX`/`PCSM`/`PCSR`）改走 `BusWorker._await_response()`：
分段读、收到完整帧即返回、最长等 1 秒。

**2. `PCSM` 之后该舵机在断电重启前不再响应任何命令。**
实测发 `#007PCSM!` → 回 `#OK!` → 此后 0 / 2 / 5 秒三次复查 007 全部无响应，
而同总线的 003–006 始终在线；断电重连后 007 回来了，且确实处于释力状态。
**这是该命令的正常行为，不是掉线，写入是生效的。**

工具据此维护一份「待断电重启」清单（`/api/status` 的 `pending_power_cycle`）：
这些 ID 在界面上标成琥珀色「已发 PCSM，待断电重启」，而不是红色「未发现」，
扫描到它重新回包时自动摘除。

### 由此产生的顺序约束

> **`PCSM` 必须是对某个舵机的最后一步操作。** 发完之后必须断电重启，才能继续和它通信。

推荐顺序：**逐个改号（改号时自动附带 `PCSM`）→ 全部断电 → 七轴接齐上电 → 逐轴零位标定**。
改号流程为「每次只接一个舵机、改完断电换下一个」，
自动附带 `PCSM` 不会多出任何一次断电。反过来先标零位再发 `PCSM` 也可以，
但绝不要在 `PCSM` 之后还想对同一个轴做标定或读数——它已经哑了。

## 持久写的共同约束

`PID` / `PSCK` / `PSMX` / `PCSM` / `PCSR` 都是掉电不丢失的写入，全部要求：

- 手输确认文本，文本不匹配直接拒绝；
- 确认框里列出将要发出的全部报文原文；
- 只发一次，不重发、不循环；
- 有舵机正在读数时，后端拒绝任何持久写（`reading_active`），界面同步禁用按钮；
- 不做一键批量，一次只写一个舵机。

**改号成功但 `PCSM` 失败时返回 partial**：ID 已经改掉且不可撤销，此时
**不允许重发 `PID`**（会打在错误地址上），应通过 `/api/startup_torque` 接口对新 ID 单独补发 `PCSM`，
请求中使用 `mode: "release"` 和对应的 `confirm_text`（例如 `PCSM 001`）。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/ports` | 枚举串口；模拟模式额外返回「模拟串口」 |
| POST | `/api/connect` | `{"port":"设备路径","baudrate":115200}` |
| POST | `/api/disconnect` | 断开串口 |
| GET | `/api/status` | 连接状态、最近扫描结果、正在读数的 ID、`pending_power_cycle` |
| POST | `/api/scan` | `{"start":0,"end":10}` |
| GET | `/api/targets` | 零位标定表与当前容差 |
| GET | `/api/reading/<id>` | 单次读 PWM |
| POST | `/api/reading/start` | `{"id":2,"release_torque":true}` |
| POST | `/api/reading/stop` | `{"id":2}` |
| GET | `/api/readings` | 所有开启中舵机的最新读数（不走队列，界面 5Hz 刷新） |
| POST | `/api/tolerance` | `{"tolerance":10}` |
| POST | `/api/set_id` | `{"source_id":0,"target_id":1,"confirm_text":"SET ID 001"}` |
| POST | `/api/calibrate_zero` | `{"id":1,"confirm_text":"CALIBRATE 001 TO 1500"}`；002/003 返回 `manual_only` |
| POST | `/api/startup_torque` | `{"id":1,"mode":"release","confirm_text":"PCSM 001"}` |
| POST | `/api/startup_position` | 固定 501：本工具不实现 `PCSD` |

三个写接口均支持 `dry_run: true`（只校验、不发送）和 `set_id` 的
`auto_release_on_boot: false`（只改号、不发 PCSM），但**界面上不再提供这两个开关**，
只能用命令行传。默认分别是 `dry_run: false`、`auto_release_on_boot: true`。

## 模拟档位

`--simulate-profile` 用于在没有硬件时演练各条失败路径：

| 档位 | 总线上的舵机 | 用途 |
|---|---|---|
| `assembled` | 001–007，读数比目标低 40 | 读数面板、零位标定成功路径 |
| `unstable` | 同上，但 `PRAD` 抖动 | 演练「关节不稳定」拒绝 |
| `new` | 只有一个出厂 `000` | 演练 ID 标定成功路径（七个按钮那条） |
| `numbered` | 只有一个已编号的 `002` | 演练手动指定源 ID 的改号（002 → 003） |
| `new-no-pcsm` | 同上，但 `PCSM` 不回包 | 演练「改号成功、开机释力失败」 |
| `multi` | `000` 和 `003` 同时在线 | 演练「多个舵机在线」拒绝 |
| `empty` | 无舵机 | 演练「未检测到舵机」 |

## 通信层来源与维护

`servo_gui/bus.py` 的协议正则、目标 PWM 表、解析函数和 `ZhonglingServoBus` 类
来源于原 `rebot_lerobot` 项目的 `tools/zhonglin_servo/servo_zero.py`，在本仓库中独立维护，
运行时不依赖原项目或本机绝对路径。

通信类保留了原脚本的方法，其中 `set_current_position_as_startup`（`PCSD`）不接入本工具的
HTTP 操作。参考上游实现更新时，需核对命令语义、目标 PWM 表和回包等待方式。
`PID`、`PCSM`、`PCSR` 等持久写由 `servo_gui/bus_worker.py` 调度，
通过 `_await_response()` 等待完整回包。
